# 授权说明（试用版 / 正式版）

万向报表（GimbalX Report） 只有**一个安装包、一套代码**。是否带水印，只取决于本机数据库里有没有有效的授权文件。

## 1. 两种状态

| | 试用版（默认） | 正式版 |
|---|---|---|
| 功能 | 完整 | 完整 |
| 期限 | 不限 | 以 `.lic` 为准 |
| 并发会话 | **1 个**（新登录顶掉旧登录） | 按 `.lic` 的 `seats`（默认 1，可签 3/5/不限） |
| 同一账号多设备 | 不允许（只保留最新会话） | 不允许（只保留最新会话） |
| 渲染页数 > 2 | 整份文档每页带 `[试用版 TRIAL]` 水印 | 无水印 |
| 渲染页数 ≤ 2 | 无水印 | 无水印 |
| CSV / JSON / XML 数据导出 | 不受影响 | 不受影响 |
| 定时任务 / API / Embed | 可用 | 可用 |

**并发席位**怎么算：同一时间在线的登录会话数（一个浏览器/一台设备算一个）。
超过席位时，**新登录会被拒绝**并提示「授权并发已满（N/N）」，已在线的人不受影响；
要先有人「退出登录」（或会话过期）才能腾出位置。

**同一账号只保留一个会话**：任何版本下，用同一账号在第二台设备登录，第一台会立即被踢下线
（页面提示“账号已在其他设备登录，本机会话已退出”）。这防的是“把 admin 账号发给全公司共用”，
需要多人同时用时请为每人建独立账号并购买对应席位。

判定发生在**渲染完成后、导出前**：以最终分页结果的页数为准（不是模板页数、不是数据行数）。
一份文档只要总页数超过 2，就整份每页加水印；2 页及以内完全无水印。

试点建议：用 2 页以内的报表做业务样张验证；超过 2 页的正式输出再导入授权。

## 2. 机器码是什么

- 机器码形如 `M7S8-6BP1-9ZFF-FSQN`（16 位，4 组），由本机操作系统安装标识计算得出：
  - Windows：注册表 `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid`
  - Linux：`/etc/machine-id`
  - 容器：默认取容器内 machine-id，建议用 `QRPT_MACHINE_ID` 固定为宿主机值
- 机器码不含硬件序列号、MAC、用户名，也不会外传；仅用于把授权绑定到这台机器。
- 重装操作系统、更换主板/系统盘、迁移虚拟机通常会改变机器码。

## 3. 获取正式授权

1. 登录后打开「系统设置 → 授权」，点「复制」取得机器码。
2. 加作者微信（见项目 README 的二维码），发送机器码 + 单位名称 + 需要绑定的机器数量。
3. 作者用离线私钥签发 `.lic` 文件并回传。
4. 在「系统设置 → 授权」点「导入授权文件」，选择 `.lic`，立即生效（无需重启）。
5. 页面会显示：授权给谁、授权编号（脱敏）、到期时间、版本。

初始化向导第 2 步也可以直接导入，适合批量部署时先发授权再交付。

## 4. 授权文件长什么样

```json
{
  "v": 1,
  "serial": "6NJKP7BJY8VS9PPFF01S164TSGC21ZQH",
  "licensee": "某某公司",
  "edition": "standard",
  "features": ["watermark_off", "scheduled_export"],
  "seats": 5,
  "issued_at": "2026-10-30T09:00:00Z",
  "expires_at": "2027-12-31T23:59:59Z",
  "machine_codes": ["M7S8-6BP1-9ZFF-FSQN"],
  "max_pages": null,
  "nonce": "…",
  "sig": "base64(Ed25519 签名)"
}
```

- `machine_codes` 可含多台机器：一份文件给一个团队用，减少来回签发。
- `seats` 是**并发席位数**：`1` 表示同一时间只能一个人在线；`5` 表示最多 5 个会话；
  填 `null` 或 `0` 表示不限。签发时用 `--seats N`（默认 1），不填即单人版。
- `expires_at` 为空表示永久。
- `sig` 覆盖除自身外的全部字段；改动任何内容都会导致验签失败。
- 程序内置公钥，只能验证作者签发的文件；私钥只在作者离线机器上，不随软件分发。

## 5. 换机、重装、扩容

| 场景 | 处理 |
|---|---|
| 重装系统 / 换机器 | 机器码会变，用新机器码重新签发 |
| 同一台机器重装软件 | 机器码通常不变，重新导入原 `.lic` 即可 |
| 虚拟机克隆 | 克隆机可能共用 machine-id；如冲突，为克隆机单独签发 |
| 容器重建（Docker） | 未固定 `QRPT_MACHINE_ID` 时机器码会变；固定后授权长期有效 |
| 增加机器 | 提供新机器码，作者在新 `.lic` 中追加或单独签发 |
| 增加同时在线人数 | 用同一机器码 + 更大的 `--seats` 重新签发（覆盖导入即可），无需换机器 |

## 6. 数据与隐私

- 授权校验完全离线：不联网、不上报、不采集使用数据。
- 授权内容加密存放在本机数据库 `app_setting` 表中，备份数据库即备份授权。
- 删除授权：目前只支持在数据库中清除（联系作者），或换机重新签发。

## 7. 常见问题

**导入提示「授权文件无效 / 签名无效」**
文件被修改过或不是作者签发；请重新获取原始 `.lic`，不要用记事本另存。

**导入提示「机器码不匹配」**
这份授权是给别的机器签发的。复制本机机器码重新申请。

**导入提示「授权已过期」**
按到期时间续期，作者会签发新的 `.lic`。

**报表只有 2 页却也带水印？**
检查预览/导出的实际页数是否为 3 页以上（页脚、空白页、子报表都会计入）。判定口径是最终渲染页数。

**水印能去掉吗？**
不能，也不允许绕过。试用版功能完整，授权后水印自动消失。

**试用版有时间限制或功能限制吗？**
没有时间限制，也不锁功能；唯一差异就是 >2 页文档的水印。

**正式版登录提示「授权并发已满（N/N）」**
当前在线会话数已经等于授权席位。先让别人在「右下角头像 → 退出登录」退出，或等会话过期；
要长期更多人同时用，请联系作者扩容（`--seats` 重新签发，通常按人数补差价）。

**能不能把一份授权/一个账号分给全公司用？**
授权绑定机器码，同一份 `.lic` 用在同一台服务器上是允许的；但**账号**始终一对一：
同一账号在第二台设备登录会踢掉第一台。多人使用请为每人建独立账号，并按人数购买席位
（例如 5 个人同时用就签 `--seats 5`）。这样既方便，也避免“买一份全公司共享”的滥用。

## 8. 给二次开发者

- 授权逻辑集中在 `backend/app/core/licensing.py` 与 `backend/app/api/v1/license.py`，其它模块只读取
  `licensing.is_trial()` / `licensing.trial_mark(page_count)` / `licensing.seat_limit()`。
- **发布包里的这些模块是 Cython 编译产物**（`app/core/{licensing,auth,sessions,dependencies}`、
  `app/api/v1/{auth,license}` 对应 `.pyd`/`.so`，包内不含同名 `.py`），用于防止改文本绕过授权。
  源码仓库仍保留 `.py` 便于开发；用官方 `scripts/build-single-*` 构建时会自动编译（`--skip-compiled-core`
  可跳过，但不建议用于对外发布）。Cython 编译要求：Windows 需 VS Build Tools，Linux/macOS 需 gcc/clang。
- 公钥常量 `PUBLIC_KEY_B64` 不应改成可被环境变量覆盖；签发私钥永不入库（`.gitignore` 已排除 `backend/.secrets/`）。
- 签发带席位的授权：`python -m app.cli lic-issue --machine <机器码> --licensee "客户名" --seats 5`（默认 1，0=不限）。
- 自行构建安装包时，请保留授权、水印与席位逻辑，否则视为违反 [LICENSE](../LICENSE)。
