# 教程 2：连 MySQL 做一张「按区域分组、带小计和总计」的销售月报

> 目标：连真实 MySQL 库，用 SQL 取数，按区域分组，每组末尾出小计，报表末尾出总计，并加条件样式（低于 1000 标红）。

## 准备

- 已完成 [教程 1](01-quickstart-csv.md)（会启动、会建报表、会拖带区）；
- 一个可连的 MySQL（本例库名 `demo`，账号有该库只读权限即可）；
- 建表与测试数据：

```sql
CREATE TABLE sales_order (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  order_no    VARCHAR(32)   NOT NULL,
  customer    VARCHAR(64)   NOT NULL,
  region      VARCHAR(32)   NOT NULL,
  amount      DECIMAL(12,2) NOT NULL,
  order_date  DATE          NOT NULL
);

INSERT INTO sales_order (order_no, customer, region, amount, order_date) VALUES
('A-1001','杭州甲公司','华东',1280.50,'2026-01-05'),
('A-1002','苏州乙公司','华东',2560.00,'2026-01-06'),
('A-1003','成都丙公司','西南',980.00 ,'2026-01-08'),
('A-1004','广州丁公司','华南',3120.75,'2026-01-11'),
('A-1005','西安戊公司','西北',760.00 ,'2026-01-15'),
('A-1006','宁波己公司','华东',4300.00,'2026-01-18'),
('A-1007','重庆庚公司','西南',1500.00,'2026-01-22'),
('A-1008','深圳辛公司','华南',2680.40,'2026-01-25');
```

## 步骤

### 1. 建数据库连接

左侧字典面板 → 新建连接 → 类型选 **MySQL** → 填主机、端口（3306）、库名 `demo`、账号密码 → 测试连接 → 保存。

连接串里的特殊字符（密码含 `@`、`#` 等）建议用界面里的分字段填写，避免拼串出错。

### 2. 写查询

新建查询，命名 `orders`，SQL：

```sql
SELECT region, order_no, customer, amount, order_date
FROM sales_order
WHERE order_date >= :start_date
ORDER BY region, order_date
```

`:start_date` 是参数（后面报表参数里会用到）。先不带参数直接执行，确认能取到 8 行。

### 3. 加报表参数

「报表」页签 → **参数管理** → 新建参数：

| 名称 | 类型 | 默认值 |
|---|---|---|
| `start_date` | 日期 | `2026-01-01` |

参数在预览前会弹框让你选，方便同一张报表按月份复用。

### 4. 排版

「组件」页签，按下表拖入（从上到下就是渲染顺序）：

| 带区 | 内容 |
|---|---|
| **页眉** | 标题 `销售月报`、右侧表达式 `报表期间：{start_date} 起` |
| **列头** | 区域 / 订单号 / 客户 / 金额 / 日期 |
| **组头** | 绑定 `orders.region` 的文本（作为分组标题行） |
| **数据区** | 五个字段 + 金额两位小数右对齐 |
| **组脚** | 文本 `小计：` + 表达式 `SUM(orders.amount)` |
| **页脚** | 页码 `第 {page} 页 / 共 {pages} 页`（以界面提供的页码函数为准） |
| **报表尾** | 文本 `总计：` + 表达式 `SUM(orders.amount)` |

关键点：**组头/组脚要设置分组字段**（属性面板里选 `region`），并且组脚必须勾选「每组重复」——否则只在最后一组出现。

### 5. 条件样式：低于 1000 标红

选中金额元素 → 属性面板 → 条件样式（或「格式 → 条件格式」）→ 新建规则：

- 条件：`orders.amount < 1000`
- 效果：字体颜色红色、加粗

点预览，`A-1003`（980.00）和 `A-1005`（760.00）应当变红。

### 6. 校验数字

| 区域 | 小计 |
|---|---|
| 华东 | 1280.50 + 2560.00 + 4300.00 = **8140.50** |
| 西南 | 980.00 + 1500.00 = **2480.00** |
| 华南 | 3120.75 + 2680.40 = **5801.15** |
| 西北 | **760.00** |
| 总计 | **17181.65** |

预览里四个小计和一个总计必须和上表一致——不一致通常是分组字段选错，或小计放到了数据区（那样会每行都出小计）。

## 常见问题

**小计每行都出现**
`SUM()` 放在了数据区。小计必须放在组脚（或报表尾），并且组脚绑定分组字段。

**分组顺序不对**
SQL 里的 `ORDER BY region` 必须保留；分组依赖数据顺序。

**参数不生效 / 预览报错**
参数名要和 SQL 里的占位符完全一致（大小写敏感）；日期参数要传 `YYYY-MM-DD`。

**连接测试成功但取数为空**
数据库账号可能只有部分表权限，或者 `WHERE` 条件把数据过滤光了——先把 `WHERE` 去掉试。

## 验收标准

- [ ] 预览弹参数框，选日期后出数；
- [ ] 每个区域一组，组头显示区域名，组脚显示小计；
- [ ] 四个小计与总计和上表一致；
- [ ] 980.00 与 760.00 两行标红；
- [ ] 导出 Excel 后，分组结构保留（不是拍平成一张大表）。
